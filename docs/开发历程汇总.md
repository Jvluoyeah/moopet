## 零、这个项目是什么

**《长夜月 · 机械狗》**，一个网页端养成系机械狗游戏：

- **开放世界**：3D 斜俯视（45~60°），四个场景（广场 / 公园 / 狗窝 / 竞技场），
  走过去按 E 交互、传送、联机看到别人的狗
- **横板对战**：竞技场 / 训练场 / 剧情关卡三套，六招制 + 防御 + 气力
- **养成与社群**：领养、等级经验、狗窝串门、排行榜、账号体系
- **移动端**：触屏摇杆 + 按钮，大世界和对战都能玩

技术栈：`w6/web`（Vite + 原生 JS + three.js）、`w6/server`（FastAPI + SQLite）、
`w6/blender`（模型库脚本）。

## 一、先记住这几条硬约束

这些是**反复验证出来的物理事实**，不是风格偏好。违反它们就会出问题：

### 1. 相机与取景

```
fov 35°（半角 17.5°），pitch 45~60°（验收要求，且必须看不到地平线）
→ 画面顶边视线 = pitch − 17.5°
→ 整幅画面都在地平线以下：**这个机位永远看不到天空**
```

- **越远的东西越往画面上缘爬**。远景物必须够矮，否则屋顶被上缘锯掉。
- **天空盒只有"画面顶边越过地面远端"时才露得出来**。所以
  **"地面铺满画面"和"能看见天空"在几何上互斥** —— 只能二选一。
  想要天空就把 `groundMargin` 调成负值（代价：地面露边），
  想要地面完整就保持正值（代价：基本看不到天空）。
- 楼高上限 ≈ `占高% ÷ 0.12`，而楼脚只落在画面 23~30% 处 → `占高 ≤ 楼脚%`。

### 2. 坐标

- `scenes/plaza.js` 用**世界坐标**（`prop(x, z, …)`）
- `scenes/others.js` 用**镜头坐标**（`prop(F, R, …)`，靠 `at()` 转换）
- **两套混用 = 转换两次**，物体飞到不知道哪里去。

### 3. 文案铁律

来自 `剧本/UI文案对照.md` + `术语校验清单.md`：

- 不出现"玩家"（用**记录员**或"你"）
- 不出现"道具 / 掉落 / 获得"
- 不出现"**选择**"这个词
- 匹配 → **对拍**；NPC → **模拟体**；服务器 → **月塔**
- 不做成就 / 每日任务
- **技术性提示不许给用户看**（要改成剧情口吻）

`_refs/_term_scan.py` 常驻扫这条，当前 **0 命中**。

### 4. 美术资产

- `w6/web/dist/breeds/` 里有 **17 张用户亲手优化过的图**。
  ⚠️ `dist` 是构建产物，`npm run build` 会用 `public/breeds/` 覆盖它。
  这 17 张已经回灌到 `public/breeds/`，构建后必须用
  `_refs/_sync_breeds.py` 核对（当前：内容不一致 0 个）。

## 二、做了什么（按主题）

### A. 世界 3D 底座

- 四场景的场景数据、构件库（`world/build.js`）、相机（`world/camera.js`）、
  足迹标尺（`world/footprint.js`）、模型接入（`world/models.js`）

- 碰撞是 **2D 的 x/z AABB**，狗永远在 y=0

### B. 模型库修复（Blender）

- `_refs/blender_audit.py` 审计 → `blender_fix_library.py` 批量修
- 用真实 `.glb`（Kenney，CC0）替换手搓几何；
  `models.js` 的 `MATERIAL_PALETTE` 按**材质名**改色，
  `GLOW_MATERIALS` 走不受光的 `MeshBasicMaterial`（窗、门、灯罩）
- **修复后的模型早就已经在世界里的**（MD5 对齐 + 实机取色双重确认过）

### C. 广场重排与放大

- 原来建筑压在活动区里 → **房子全摆到外侧、朝内，中间留给玩家活动**
- 广场放大：`2200×1700` → **`2800×2150`**，相机 `dist 2700` → **`3300`**
- 传送点从 z=1620 挪到 **z=1944**（原来正好盖住出生点的回头路，
  e2e 里"按住 Shift"会走过去被传走）

### D. 穿模治理 —— 两把尺

| 尺 | 量什么 | 文件 |
|---|---|---|
| 占地 + 真投影 | 两两占地是否相交、取景百分比 | `web/tools/layout_check.mjs` |
| 真实 AABB 最低点 | 有没有东西悬空 | `_refs/_floater_check.py` |
| **地面范围** | 有没有东西**站在地面之外** | `_refs/_ground_scan.py` |

> ⚠️ 第三把尺是补出来的：前两把都抓不到"脚底正好是 0、但脚下那块地面不存在"
> 这一类 —— 用户指出过两次（公园那排远处的树、还有花和灌木）。
> 判据是 `size + groundMargin` 算出的地面矩形。当前四场景 **0 个**。

### E. 建筑细节按用户要求删减

- 招牌挑出的横杆、房顶的横杆、**招牌柱子**、**屋脊横条** —— 全删

**"现在的竞技场的样子完全舍弃"** —— 照 `剧本/图片/场景/月光竞技场.png` 重做：

- 四面板砖墙围起来（远墙留 520 宽门洞，门洞里垫一层更暗的板）
- 两侧 **7 级木看台**（`bleachers`），坐板外挑、带踢脚挡板
- 顶上四盏 **吊灯 + 光锥**（`ceilinglamp`）
- 地上 **灯光斑 + 白色球场线**（`lightpool` / `courtline`）
- 尽头门洞前 **登记桌椅**（`deskset`），椅子在桌后、**面朝场地**
- 原来的三栋楼（对战登记处 / 训练关卡 / 观战席）全删

新构件都登记进了 `PROP_BUILDERS` 和 `footprint.js` ——
**不登记就会落到默认 200×200**，检查器给出的数字全是错的（第一版就是这样）。

### J. 公园重建

照 `剧本/图片/场景/长夜月公园.png` 重做，两栋楼（飞盘场 / 凉亭）撤掉：

- **绿色草地**（原来米白，夜里发灰不像草坪）
- **一条弯过来的土路** —— 为此**新写了 `path` 构件**：
  这个 kind 一直挂在贴花名单里，**但从来没有实现**，场景里写了也不画、还不报错
- 沿路四盏灯 + 每盏一圈地面光斑
- 一棵加高到 900 的大树 + 长椅 + 一盏灯
- 杂草、野花、灌木

### K. 天空盒

按 three.js 手册（<https://threejs.org/manual/#backgrounds>）的做法：
`scene.background` + **等距柱状贴图**（`EquirectangularReflectionMapping`），
程序生成夜空渐变 + 星 + 月亮 + 地平线上的城市剪影。

坑也记在这条里：

- 月亮必须画在**地平线略下方**（约 −25°）—— 因为相机整幅都在地平线以下，
  画在正上方永远采样不到
- "把地面收窄好让天空露出来"这条路**转过视角就穿帮**（浮空路缘、贴片幕布像一堵墙）
  → 加了 `camera.yawRange` 每场景转向范围；路缘在地面收窄的场景**不画**；
  幕布**撤掉**（天空盒本来就是 360° 的）
- **最终取舍**：`groundMargin` 回到正值，地面铺满、天空基本看不到 ——
  用户选定"地面要完整"

### L. 灯光与材质

- **灯效做进 `makeLamp` 构件里**（不是给广场单独补一个）：
  灯下暖光圈 + 灯箱改 `MeshBasicMaterial`（原来是有 emissive 的 Lambert，
  夜光太暗乘下来是灰的，看着像没开灯）。**四个场景所有路灯自动受益**。
- **模型材质一律双面**：Kenney 的树冠/灌木/草叶都是单面片，
  从背面看被剔除 → 表现是"树顶是空的"。斜俯视会同时看到正反两面，双面是必须的。
- **石砖地面**（`ground.kind: 'brick'`）：错缝铺法 + 每块砖微差 + 确定性伪随机。
  广场的棋盘格太整、像纸面，石砖才像"这个广场是铺过的"。

### M. 文案治理

- 一条技术提示「位置同步异常，已忽略这一步」→ 改成
  **「刚才那一步没算数，再走一次就好。」**，排查信息改走 `console.info`
- 领养卡上的内部编码 `breeds/samoyed` → 改成「形象包」
- 修掉两处页面印出**字面的 `null`**（见踩坑表）

### N. 移动端适配

- **开放世界**新增 `createWorldPad`：左下四方向、右下 跳/跑/交互；
  发**真实键盘事件**，和键盘同一个入口，行为不分叉；
  空格（跳）是单次动作，只发 `keydown` 不发 `keyup`
- **对战**：原来竖屏只显示「把手机横过来」、CSS 把战斗界面藏掉 →
  改成**单列**（舞台占满宽度、信息栏落下面）。
  注意：**不能把信息栏藏掉**，开局按钮就在里面
- **顶栏折两行**（品牌+账号 / 四个页签）—— 一行摆不下，
  页签被挤出去后**和"主人"链接压在一起**，手机上点不到"训练记录"
- 目录（`.catalogue`）在手机上隐藏 —— 它占 430px

## 三、踩坑速查表

**这一节是全文最该看的部分。** 全都是"不报错、静默失效"的那一类。

| 现象 | 根因 | 教训 |
|---|---|---|
| 东西飘在半空 | `paperBox` 的原点在**盒子底部**，代码却写 `position.y = h/2` | 用 `_floater_check.py` 扫 |
| 页面上出现 `[object Object]` | `h(tag, props, ...children)` 的 `onclick` 写到了第三个参数 | 事件一律放 props |
| 加了新 kind 场景里却没有 | `MODEL_KINDS` 是写死的 Set | kind 要登记三处：`PROP_BUILDERS` / `footprint` / `MODEL_KINDS` |
| 写了 `{kind:'path'}` 什么也没画 | 这个 kind 只有名字、没有构件 | 贴花名单 ≠ 有实现 |
| **摇杆在 DOM 里根本没有** | 挂在 `wrap.replaceChildren(...)` **之前**，被那句清掉了 | 挂载要在结构稳定之后 |
| **摇杆画出来了、按上去没反应** | 祖先 `.sheet` 的入场动画留下 `transform`，`position: fixed` 被它困住（按钮落在 y=1806 / 屏高 915） | fixed 元素要挂在 `body` 上 |
| 手机上目录占掉半屏 | 页面里有**两个** `<aside>`：`.catalogue`（目录）和 `.aside`（便签），隐藏错了那个 | 类名对，但**对的是另一个元素** |
| 舞台高度塌成 124px | 我写的 `height: auto` 覆盖掉了原来的 `clamp(360px,52vh,620px)` | 覆盖前先看原值 |
| 横屏按钮只有 34px 高 | 触控尺寸规则写在 `@media (max-width: 560px)`，横屏宽 915 不满足 | 该按 `pointer: coarse` 判，不该按宽度 |
| 页面上印出字面 `null` | 原生 `replaceChildren(null)` 会把 null 当**文本**插进去 | 用 `lib/dom.js` 的 `replaceChildren`（会过滤） |
| `dvh` 写了没生效 | 旧 Chromium 不识别，整条声明被丢弃 | 前面补一行 `vh` 兜底 |
| 光晕里的狗出现方块边缘 | 光斑的 `renderOrder` 比角色高，加色混合照亮了角色贴图的方块 | 贴地光效一律**负** renderOrder |
| 树顶是空的 | 模型是单面材质，背面被剔除 | 受光材质一律 `DoubleSide` |
| 看台"朝墙坐" | 局部 +z 的朝向算反了（`rot = YAW ∓ π/2` 指到了外侧） | 转向类改动要用截图验证，别只算 |
| 远处道具飘在天上 | 它们站在**地面矩形之外**（脚下 y=0，但那块地面不存在） | `_ground_scan.py` |
| 楼顶被上缘锯掉 | 远景楼太高（越远越往上爬） | 占高% ≈ 0.12 × 高度 |
| 服务端拒绝位置导致回弹 | `too_fast` / `out_of_bounds` 的提示直接给用户看了 | 技术信息改走 console |
| **真机上 UI 全乱** | CSS 注释正文里写了注释的起止符号 → 注释提前结束 → **紧跟其后的整个 `@media (max-width: 820px)` 块被丢掉** | 见下面「真机那一课」 |
| 布局只在 412px 下成立 | 所有移动端尺寸都是写死的 px（按钮 58px、横幅 `max-width:60%`、页签 `flex-wrap:nowrap`） | 触控按钮改 `clamp(40px,13vw,64px)`；页签**允许折行**；宽度谱 320/360/412/578 都要验 |

## 三点五、真机那一课（值得单独记）

模拟里全绿，用户一上真机就截图回来说"UI 错乱"。查下来是**三个叠加的原因**：

1. **写死的 px 尺寸**。真机的 CSS 视口取决于屏幕密度和系统显示缩放 ——
   1440 物理像素的机器实际可能只有 **320**。写死 58px 的摇杆在那上面占
   **18% 屏宽**，一个按钮顶五分之一屏。
   → 全部改成 `clamp()`，并且**沿 320/360/412/578 四个宽度都验**。

2. **横幅 `max-width: 60%`**。320px 下只剩 192px，"长夜月广场"被折成
   **一个字一行**。
   → 窄屏下改成整行（信息条折两行：地点在上、按钮在下）。

3. **`flex-wrap: nowrap` 是我自己加的**。四个场景页签被压扁、文字溢出被裁，
   真机上显示成"场 / 园 / 窝 / 场"。
   → 挤不下就**老实折行**，比"看起来整齐但字没了"强。

而**放大这些症状的那颗雷**，是 CSS 注释里写了注释的起止符号：
注释提前结束，后面的正文变成活的 CSS，把整个 `@media (max-width: 820px)`
块吃掉了 —— 手机端最关键的那一整块规则（触控层定位、画布高度、页头压缩）
**一条都没生效**。

> 教训有两条：
> ① **注释正文里不许出现注释的起止符号**（我就是在那段"解释这个坑"的注释里
>    又犯了同一个错，第二次把同一块规则吃掉）；
> ② 改完 CSS 不能只看源码在不在 —— 要在页面里查 `getComputedStyle`，
>    或者看构建产物里这条规则落在哪个 `@media` 里。

排查这类"规则明明写了却不生效"，顺序是：
`getComputedStyle` 看实际值 → 构建产物里找这条规则 → 看它在哪个 `@media` 里 →
扫注释结构。**别从源码往下猜。**

### 移动端

本次工作**之前**就已经有一个 `e2e_touch.py`，它验的是对战触控的三件事：
触屏上真的出现虚拟按键（桌面上不该出现）、点按钮真的能驱动角色、
以及 **快速点按不会丢输入**。

> 最后那条背后有个容易被忽略的设计：模拟一帧约 7.8ms，手指点一下如果短于一帧，
> 引擎采样不到就是"没反应"。所以触控层给了 **最小闩锁 90ms**（`MIN_LATCH_MS`）。
> 这条不写下来，下次改触控很容易把它当多余代码删掉。

本次新增的三个脚本与它互补（覆盖大世界、UI 布局、横屏、反向检查）：

| 脚本 | 验什么 |
|---|---|
| `e2e_mobile.py` | 触控层挂载 / 四个方向键 + 跳跑交互 / **按住 ↑ 狗真的走** / 对战页也有按钮 / **桌面端不该出现触控层** / 页面上没有字面 null·undefined·NaN |
| `e2e_mobile_battle.py` | 竖屏对战：没有"把手机横过来"挡着 / 舞台真有画面 / **点招式键角色真的出招** |
| `e2e_mobile_ui.py` | 逐页**命中测试**（`elementFromPoint`：顶层不是它就算被挡）+ 触控目标 ≥44px，**竖屏 6 页 + 横屏 2 页** |

> `e2e_mobile_ui.py` 值回票价：它抓到"手机上点不到训练记录"和"横屏按钮只有 34px"
> 两个肉眼没看出来的问题。**几何上不重叠 ≠ 点得到** —— 只有命中测试算数。

**最近一次全量回归**：18 个套件全绿。

## 七、几处刻意留下的取舍（不是没做完）

1. **天空 vs 地面完整** —— 几何互斥，用户选定"地面要完整"（`park.groundMargin = 400`）。
   想要月亮就改成负值，同时接受地面露边。
2. **公园转向范围 ±0.35 rad** —— 为了不穿帮，代价是转不出设计好的取景。
   验收要求"拖拽能旋转视角 >0.2 rad"，这个值满足。
3. **竖屏对战舞台高度 42vh** —— 挤，但能打。手机用户至少不会完全打不了。
