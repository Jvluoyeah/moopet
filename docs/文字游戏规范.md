# 长夜月 · 文字游戏（AVG）规范

> **给正在写文本游戏的 agent 的执行规范。**
>
> 配套阅读：`w6/docs/世界观设定.md`（剧情底本，**必须通读**）。
> 引擎文档：<https://docs.avg-engine.com/extensions/intro> 及其同栏目页面。
>
> **硬约束：只做文字游戏本身，不改现有架构。**
> 具体含义见最后一节「十、不许动的东西」——那条比这份文档里其它所有内容都重要。

---

## 一、这个文字游戏是什么

**《长夜月 · 档案册》**——一个以「记录员整理册子」为框架的文字游戏。

玩家已经在网页那边养了一只机械狗（八原型之一）。文字游戏做的不是重讲一遍养成，
而是**把册子上那几页空白的、只有真人才能填上去的东西补完**：

> 档案册上有一栏叫「**它今天做了什么**」，玩家一直没填。
> 记录员（玩家）翻开册子，从这一栏开始补。

所以整个文字游戏是**在册子内部发生**的：每一章是一页，玩家的选择是**记录**，
不是"指挥狗去打怪"。这个框架决定了所有演出的调子：**纸、墨、印章、翻页**，
不要出现"关卡""血量""战斗"这类词。

---

## 二、它必须对底层数据做出反应

这是这份规范的核心。**文字游戏不是通用剧本，它必须"认出"玩家带来的是哪只狗。**

可用的数据（**全部来自现有接口，不需要后端改任何东西**）：

| 字段 | 来源 | 说明 |
|---|---|---|
| `breed_code` | `DogOut.breed_code` | 八个原型之一，**最主要的反馈维度** |
| `breed_name` / `subtitle` | `DogOut` / `BreedOut` | 例：`边境牧羊犬` / `智力天花板` |
| `name` | `DogOut.name` | 玩家取的名字。**所有对白都用它** |
| `level` / `total_exp` | `DogOut` | 等级决定项圈色：LV.1 普通 / LV.10 稀有 / LV.20 史诗 / LV.30 传说 |
| `personality` | `DogOut.personality` | 性格标签（已有字段，直接用） |
| **`motto`** | `DogOut.motto` | **口头禅——最重要的个性化钩子**，见 §5 |
| `stats` | `DogCardOut.stats`（`power/agility/wisdom/affinity`） | 四维，阈值判定用 §6 |
| `achievements` | `DogOut.achievements` | 彩蛋分支 |
| `social_level` / `friendship_points` / `visits_received` | `DogCardOut` | 决定广场上别人认不认识它 |
| 关卡成绩 | `TrainingLevelOut`（`cleared/stars/best_ticks`） | 没见过世面的狗遇到模拟体会怕 |
| 旧物 | `TrainingDrop`（`尘埃齿轮/磨牙绳结/螺旋桨叶/褪色的毛线`） | 见 §7 |

### 三种档案来源（优先级从高到低，后两种必须永远可用）

| 优先级 | 来源 | 什么时候用 |
|---|---|---|
| 1 | **宿主注入**——被嵌进网页时由外层传入 | 可选，锦上添花 |
| 2 | **档案码导入**——玩家从网页复制一串码，粘进游戏 | 主要方式 |
| 3 | **开头手选**——游戏开头问"你带的是哪只狗" | **兜底，必须实现** |

> ⚠️ **第 3 条是硬要求。** 只要它存在，这个文字游戏就永远能单独跑——
> 不依赖网页、不依赖后端、不依赖我这边任何改动。前两条是加速器，不是前提。

**档案码格式**（我方按这个格式导出，你按这个格式解析）：

```
MP1-<base64url(UTF-8 JSON)>
```

JSON 形状就是 §2 那张表的扁平化，**字段名固定**：

```json
{"v":1,"id":97,"name":"短腿","breed":"corgi","breed_name":"柯基",
 "level":12,"exp":340,"personality":"稳重","motto":"回来啦",
 "stats":{"power":64,"agility":70,"wisdom":72,"affinity":80},
 "achievements":["first_clear"],"cleared":["L1","L2"],"stars":{"L1":3,"L2":1},
 "drops":["尘埃齿轮","磨牙绳结"],"social":7,"friendship":128,"visits":9}
```

解析失败、字段缺失、版本号不认识 → **一律退回第 3 种（手选）**，不要报错中断。

## 三、扩展怎么搭（AVG Engine）

按 AVG Engine 的扩展模型，整个文字游戏是**一个程序扩展**（`moopet-dossier`），
包含：一个 `saveSchema`、一组 `method()`、若干 `settings`，外加**可选**的 `render()`。

### 3.1 模块骨架

```ts
import {
  Extension, extension, defineSave, method, settings,
  type SettingsBuilder, type SaveAPI,
} from "@avg-studio/sdk";

type DossierSave = {
  profile: PetProfile | null;     // 导入的档案
  shown: readonly string[];       // 已经说过的话（见 §5 的"不能重复还同一句"）
  relics: readonly string[];      // 这一周目在剧情里收到的旧物
  chapter: number;
};

@extension({ id: "moopet-dossier", label: "档案册 · 长夜月" })
export class MoopetDossier extends Extension {
  static saveSchema = defineSave({
    profile: { type: "object", persistence: "slot", default: null },
    shown:   { type: "list",   persistence: "slot", default: [] as string[] },
    relics:  { type: "list",   persistence: "slot", default: [] as string[] },
    chapter: { type: "number", persistence: "slot", default: 0 },
  });

  static settings = settings((s: SettingsBuilder) => ({
    strictLore: s.boolean("严格按设定口径校验台词").default(true),
    showDebug:  s.boolean("显示档案调试面板").default(false),
  }));

  // 方法见 §4
}
```

> `saveSchema` 的字段类型/持久化取值，以及 `defineSave` 的完整字段表，
> 见引擎文档「存档 Schema」。上面 `object` 只是示意，**具体类型名以该页为准**——
> 如果 `object` 不被支持，就用 `json` 或把 profile 拆成若干个标量字段
> （`breedCode` / `dogName` / `level` / `motto` / `wisdom` …），**拆开更稳，推荐拆**。

### 3.2 拆开存（推荐）

```ts
static saveSchema = defineSave({
  breedCode: { type: "string", persistence: "slot", default: "" },
  dogName:   { type: "string", persistence: "slot", default: "" },
  level:     { type: "number", persistence: "slot", default: 1 },
  motto:     { type: "string", persistence: "slot", default: "" },
  wisdom:    { type: "number", persistence: "slot", default: 0 },
  agility:   { type: "number", persistence: "slot", default: 0 },
  power:     { type: "number", persistence: "slot", default: 0 },
  affinity:  { type: "number", persistence: "slot", default: 0 },
  clearedCsv:{ type: "string", persistence: "slot", default: "" },  // "L1,L2"
  dropsCsv:  { type: "string", persistence: "slot", default: "" },
  shownCsv:  { type: "string", persistence: "slot", default: "" },
  source:    { type: "string", persistence: "slot", default: "manual" }, // host|code|manual
});
```

## 四、要暴露给剧本的方法（**这是给剧本作者的接口**）

方法名一律 kebab-case，前缀 `档` 的概念统一叫 `dossier`。

### 4.1 条件方法（必须有 `returns`，供 `If` 使用）

| 方法标题 | id | schema | returns | 作用 |
|---|---|---|---|---|
| 是不是这个原型 | `is-breed` | `breed: enum`（八选一） | `boolean` | **最常用的分支条件** |
| 属不属于这一族 | `breed-in` | `group: enum`（`机灵/亲人/警觉/憨厚`） | `boolean` | 少写一堆 if，见 §8.2 |
| 四维达标 | `stat-at-least` | `stat: enum(power/agility/wisdom/affinity)`，`value: number` | `boolean` | §6 的阈值判定 |
| 等级至少 | `level-at-least` | `value: number` | `boolean` | |
| 通了这一关 | `cleared` | `level: enum(L1..L4)` | `boolean` | |
| 有这件旧物 | `has-relic` | `relic: enum(四选一)` | `boolean` | |
| 档案到位了没 | `has-profile` | — | `boolean` | 手选兜底时用来分支 |
| 口头禅是什么 | `motto-text` | — | `string` | 取玩家的口头禅填进台词 |
| 它叫什么 | `dog-name` | — | `string` | 同上 |
| 它的项圈什么色 | `collar-tier` | — | `string` | `普通/稀有/史诗/传说` |
| 这一句说过了没 | `said-before` | `lineId: string` | `boolean` | 防止同一句话重复"还"（§5） |

> 条件方法**必须**声明 `returns`，否则不会出现在 `If` 的候选里。
> 返回类型不符、扩展停用、抛错时，引擎会把该条件**安全地当成不满足**并记警告——
> 所以方法要写得"宁可不满足也别乱返回"。

### 4.2 动作方法（演出用）

| 方法标题 | id | schema | 作用 |
|---|---|---|---|
| 导入档案 | `import-profile` | `code: string(multiline)` | 解析 §2 的档案码，写进存档；失败返回不抛错 |
| 翻开新的一页 | `turn-page` | `chapter: number` | 章首演出（翻页 + 盖章） |
| **它说** | `it-says` | `lineId: string`，`text: string` | **播狗的一句台词，见 §5** |
| 记下这句 | `remember-line` | `lineId: string` | 把说过的句子记进 `shown` |
| 收进旧物 | `take-relic` | `relic: enum(四选一)` | 剧情里捡到旧物 → 写进存档 + 图鉴 |
| 盖章 | `stamp` | `text: string` | 在册页角落盖一个章（纯演出） |

**每个动作方法都要写 `skip`**（玩家按 Ctrl 快进时用）：跳过动画，只保留状态变更。
不写 `skip` 时引擎会 fallback 到 `run`，那快进时会把动画也放一遍。

### 4.3 可选：调度策略

只有当你要做**地图选页/回合结构**时才用 `scheduleStrategy()`（见引擎文档）。
本项目**默认不需要**——章节是线性的，用普通 fragment 跳转即可。
**不要为了用而用。**

## 五、狗怎么说话（**这一节最容易写崩，逐条执行**）

世界观的规矩：**它只会说"被装进去的话"**——它说的每一句，
都是**之前有人对它说过的**。详见 `世界观设定.md` 第二章。

### 5.1 四条硬规则

1. **短。** 一句 ≤ 15 个汉字。超了就删，不是压缩。
2. **少。** 一次对话它最多开口**一次**。大部分时候它在叫、在哼、在用鼻子顶你。
3. **是"还"，不是"说"。** 每写一句它的台词，先回答：**这句话是谁、在什么时候对它说的？**
   答不上来就不要写。
4. **不解释、不推动剧情。** 它不指路、不复述设定、不安慰人。它的台词只干一件事：
   **让玩家想起自己说过什么。**

### 5.2 台词从哪来（**这就是底层数据怎么变成文本的地方**）

按优先级取，前面的没有就往后掉：

| 优先级 | 来源 | 例子 |
|---|---|---|
| 1 | **玩家的 `motto`** | 玩家写的是"回来啦" → 关键时刻它说"回来啦。" |
| 2 | **品种专属的"原件记忆"** | 见 §8.1 的「原型记忆」列 |
| 3 | **通用兜底句** | 每个"还话点"配一句不带品种色彩的（如"不走。"） |

> **`motto` 是这套设计里最重的一颗子弹。**
> 玩家自己写的那句话，在剧情关键处被狗原样还回来——这是整个文字游戏最有冲击力的一刻。
> **每一章至少安排一个"还话点"**，并且**必须优先用 `motto`**。
> `motto` 为空时（玩家没填）走优先级 2/3，不要显示空白。

### 5.3 不能重复"还"同一句

用 `said-before` / `remember-line` 记账。同一个 `lineId` 只还一次。
理由：这狗一辈子只能说有限的几句，重复说同一句会让"它记得"这件事贬值。

### 5.4 其它角色的说话方式（对照用）

| 角色 | 说话方式 |
|---|---|
| **记录员（登记处那位）** | 陈述句、短、不解释。*"先报上名来。"* 她从不说"欢迎来到长夜月"这种话 |
| **月塔的调度员** | 公事公办、术语多、偶尔露出一点疲态 |
| **街坊** | 随口、带点长夜月的生活气（灯、月亮的位置、电费） |
| **狗** | 见上 |

## 六、阈值口径（四维怎么变成条件）

四维是 0–100 的整数，但**文字游戏里只认三档**，不要写精确比较：

| 档位 | 判定 | 意义 |
|---|---|---|
| 高 | `≥ 75` | 这件事对它来说很轻松 → 给"轻松"的文本 |
| 中 | `≥ 55` | 能做成，但要费点劲 → 给"吃力"的文本 |
| 低 | `< 55` | 做不成 → 给"失败但可爱"的文本 |

**判定优先级**：**品种 > 四维 > 等级**。

理由：玩家选品种时是在选**性格**，这是他最有感知的一次选择；
四维是品种的派生结果（柯基必然敏捷低、比熊必然体力低），
所以**品种分支已经覆盖了大部分情况**，四维只用来做同一品种内的细分。

**失败分支不许写成惩罚。** 低属性失败要写成"它做不到，但它有别的办法"或者"它干脆不干了"。
长夜月不是个靠数值卡人的世界。

## 七、旧物的处理

四种旧物（尘埃齿轮 / 磨牙绳结 / 螺旋桨叶 / 褪色的毛线）在文字游戏里是**情感道具，不是收集品**。

* **不要写"获得道具 x1"**，要写**它叼回来**：*"它把一小截毛线放在你脚边，抬头看你。"*
* 不给旧物标价格、不给属性加成。**一标价就变成道具了。**
* 玩家已有哪些旧物（`drops`）会改变台词：有「磨牙绳结」的狗对"真狗的玩具"有反应；
  只有「螺旋桨叶」的狗会把天上那些机器当同类。

## 八、反馈矩阵（**这张表就是"根据底层结构做反馈"的落地**）

### 8.1 八原型的反馈卡

每张卡三件事：**它擅长什么 / 它在文本里的行为特征 / 它的"原型记忆"（喂给 §5.2 的台词来源）**。

| 原型 | 擅长（走这条分支时顺） | 行为特征（写台词与旁白时体现） | 原型记忆（它会还的话） |
|---|---|---|---|
| **萨摩耶** 微笑天使 | 社交、亲近陌生人、安抚 | 见谁都摇尾巴；**没有警觉心**，遇到可疑的人也往上凑 | *"回来啦。"* |
| **边境牧羊犬** 智力天花板 | 解谜、听复杂指令、看穿机关 | **会自己开院门**；容易无聊，无聊就拆东西；NPC 会评价"这狗聪明得吓人" | *"再来一次。"* |
| **金毛** 温柔大个 | 什么都不差（保底路线） | 不争、不抢、不叫；关键时刻挡在前面 | *"给我。"* |
| **柯基** 短腿电臀 | 耐力、长距离、钻低处 | **上不去台阶、跳不上台面**（要专门写这个）；脾气比腿长，从不掉队 | *"等我。"* |
| **柴犬** 独立小狐狸 | 观察、独处、夜间 | **认人慢**：前两次互动不回应；一旦认了，只有它有专属支线 | *"……"*（先是不说话，认了之后才开口） |
| **德国牧羊犬** 可靠守卫 | 警戒、守夜、追踪 | 夜里能察觉别人察觉不到的；对陌生人冷淡但不凶 | *"我在这。"* |
| **哈士奇** 雪原话痨 | 跑、体力、闹 | **话最多**（但仍受 §5.1 限制：一句 ≤15 字、一次一句）；智力偏低导致"听懂指令"类分支**故意失败** | *"走了走了。"* |
| **比熊** 棉花糖 | 亲和、看人脸色 | 体力弱，长距离/战斗分支会累；最会读空气 | *"抱。"* |

### 8.2 分组（少写一堆 if）

八个原型按**脾气**归四组，条件方法 `breed-in` 用这个：

| 组 | 成员 | 共同反馈 |
|---|---|---|
| `机灵` | 边牧、柴犬 | 会观察、会拆解问题、不愿被指挥 |
| `亲人` | 萨摩耶、金毛、比熊 | 对陌生 NPC 初始好感高 |
| `警觉` | 德牧、哈士奇 | 夜里/危险场景有额外感知；对陌生人冷淡 |
| `憨厚` | 柯基 | 抗造、耐力好、想不到弯弯绕 |

> 分组的意义：**剧本作者只用记四组**，写不出八种分支时至少能写对四组。
> 但**每只狗的专属支线仍然要单独写**（见 §9）。

### 8.3 等级与项圈色

| 等级 | 档位 | 在文本里的作用 |
|---|---|---|
| LV.1–9 | 普通（灰） | "新的？"——街坊会这么问 |
| LV.10–19 | 稀有（蓝） | 广场上有人认得它 |
| LV.20–29 | 史诗（紫） | "这条街的人都认识它" |
| LV.30+ | 传说（金） | 月塔会复印一份它的档案 |

**项圈色是"它被陪了多久"的公开读数**——NPC 看狗先看项圈，这是长夜月的礼节。
这是免费的性格化道具，**每一章至少用一次**。

## 九、章节结构（把 §8 装进剧情）

沿用 `世界观设定.md` 的主线骨架，但**文字游戏只做册子内部能发生的事**：

| 章 | 标题 | 反馈重点 |
|---|---|---|
| 序 | 一本空册子 | 手动选狗 / 导入档案；记下名字与口头禅 |
| 一 | 它今天做了什么 | **第一次"还话点"**（用 `motto`）；品种行为特征登场 |
| 二 | 石环上的编号 | 社交数据（`social_level`/`visits`）决定 NPC 认不认识它 |
| 三 | 对拍 | 敏捷/智力分支；**赢了输了都要能往下走** |
| 四 | 册子里的训练场 | 关卡成绩（`cleared/stars`）改变它对模拟体的反应 |
| 五 | 它叼回来的东西 | 旧物（`drops`）；**本章是第二次"还话点"，仍然是 `motto`** |
| 六 | 装进身体里 | 等级/项圈色收束；结局 |
| **专属支线** | 每只狗一条 | **只在选了该品种时出现**，是品种反馈的最高形态 |

**专属支线必须真的专属。** 不要写成"通用支线换了个名字"——
边牧那条就该是"它自己把院门打开了"，柯基那条就该是"它上不去那道台阶"。

## 十、不许动的东西

> **这一节优先级最高。违反其中任何一条，整份工作都要返工。**

1. **不改网站的任何代码。** 文字游戏是**独立工程**（AVG Engine 项目），
   通过 §2 的档案码/手选对接。**不要**去改 `web/` 或 `server/` 的任何文件。
2. **不新增后端接口、不改数据模型。** §2 那张表里的字段**全部已经存在**。
   需要新字段 → 先写成"这一版拿不到，走兜底"，然后报给我。
3. **不改游戏逻辑。** 战斗、关卡、经济、等级结算——一个字都别碰。
4. **不发明与世界观冲突的设定。** 太阳不会回来；狗不会长篇大论；
   机械狗不是真狗的替代品；旧物不标价。详见 `世界观设定.md` 第十三节。
5. **不用"玩家/用户/角色"称呼。** 用**记录员**。用词表见世界观文档。
6. **不把文字游戏做成数值游戏。** 没有战力、没有装备、没有抽卡。
   四维只用来分支，不用来算数。
7. **不硬编码八套完整剧本。** 用 §8.2 的分组 + §8.1 的行为特征，
   只在**专属支线**那里真正分八条。
