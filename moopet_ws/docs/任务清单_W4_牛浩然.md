## 一、本周任务（W4 · 8.24–8.30）

### 任务 0：上手 + 认数据（半天，周一前完成）
- 跑 `python standalone_demo_w4.py --fast`，看最后"成长日记"一节——**屏幕上那条日记就是你要展示的数据**；
- 读 `src/moopet_dog/moopet_dog/decision/diary.py`：`DogDiary`（读写 diary 表，`latest(n)` 直接可用）、`build_diary_content`（日记成文格式）；
- 读 `schema.sql` 的 `diary` 表：`id / date / content`，**UNIQUE(date) 一天一条**（重复写是覆盖，不是追加）；
- 确认 DB 位置：与经验库**共用同一个 SQLite**（`~/.moopet/moopet.db`，W3 已和你敲定共用）。
- **验收**：给李文扬一句确认"日记读库路径 + 字段够不够用"，有缺口当场提。

### 任务 1：日记 API + 前端日记页 — 本周核心
- **目标**：后端出日记接口（按天取/按周取），前端做日记页展示。
- **复用**：`diary` 表（已在落库）+ `DogDiary.latest(n)`。
- **验收**：
  - 接口能按日期取单条、按周取列表；
  - 日记页能看到"某天日记全文 + 日期"，样式贴合成日记本感觉（创意交给你）；
  - 无 Ubuntu 环境时，先用 demo 生成的日记数据造测试库，页面先行。

### 任务 2：心情时间序列 API + 前端心情曲线
- **目标**：心情随时间变化的曲线页。
- **数据源**：`/dog/state`（`DogStateMsg`，level/emotion）的历史广播——注意 W2 起该话题就有，存历史即可（web 侧定时拉取落表，或订阅记录）。
- **验收**：曲线能看出"互动多 → happy、被冷落 → neutral/低落"这种趋势；跟情感账户对得上（demo 里账户 20→32 那段如果画出来应是回升线）。

### 任务 3：周报 API
- **目标**：按周汇总互动/答题/日记，出一份"这周我们处得怎么样"的周报数据。
- **复用**：`quiz_record`（W3 答题记录）+ `daily_stats()` 的统计口径（pet/quiz_correct/walk…），照抄口径别另造。
- **验收**：给定周区间返回汇总 JSON；前端可不画（W5 火花页再消费）。

### 任务 4：联调对齐（跟李文扬 30 分钟）
- 对齐：日记/心情/周报三个接口的字段与错误约定；确认要不要 web 侧直读 SQLite 还是走 ROS 话题镜像（沿用 W3 "共用同一个库"的结论）。
