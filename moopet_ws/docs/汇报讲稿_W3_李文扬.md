## 第 3 页 完成情况一览（重点页，约 60 秒）

**屏幕上有**：8 行交付物表（类型=排期/补充/质量，状态 ✅）+ 1 行 ⏳ Ubuntu 待验证。

**主讲话术**：

- *"排期"和"补充"怎么区分？* 排期是计划里的，补充是我为了让闭环可演示主动加的，两者都已完成。

## 第 4 页 成果① 答题闭环（quiz_node，约 45 秒）

**屏幕上有**：6 个要点卡片（出题/判题、连击奖励、难度降档、等级解锁、判题桥接、挂入决策引擎）+ 底部接入点说明。

**主讲话术**：
> "第一个成果是答题闭环。用户出题、作答、判题都是真实逻辑：连对 5 题加 50、10 题加 100；连错 3 题难度自动降一档，照顾体验；题库按等级解锁——语文数学 3 级、英文常识 8 级、科学编程 15 级、自定义 20 级，这是产品设计的养成节奏。特别说明一点：判题走 `/dog/combo` 这个服务，和网页端判题是同一个接口，队友的答题页可以直接对接。"

**追问应答**：
- *连击奖励和难度降档的数值依据？* 来自我们产品规则文档（狗2.md）和排期设计，不是我随意定的，都有单测兜底。
- *答题记录存哪？* 写进 SQLite 的 quiz_record 表，表结构第一周建库时就预留了。

## 第 5 页 成果② 行为决策引擎骨架（约 45 秒）

**屏幕上有**：左侧目录树（decision/ 结构、W4 空节点位置）、右侧"本周已跑通"（绿）和"W4 将填充"（橙）两个框。

**主讲话术**：
> "第二个成果是决策引擎骨架。左边是目录结构：行为树的核心（Sequence/Selector/Fallback 这些运行器）、条件节点、行为节点、树定义，加上决策引擎入口和 ROS 节点。它不是摆样子的——绿色框是本周已跑通的：答题事件进来，行为树路由出'答对表扬、答错鼓励'，联动语音和动作，状态卡实时刷新。橙色框是 W4 要填的：性格演化、情感账户、主动关怀、纪念日，这些位置我都先占好位了，下一步直接填逻辑。"

**追问应答（关键问题）**：
- *是不是只是空壳？* 不是。它已经是可运行的事件路由，答题闭环真的在走它。只是"性格、纪念日"这些更复杂的决策要等 W4 填，框架和接口本周就绪、不用动。
- *为什么先做骨架再做逻辑？* 先把数据怎么流、事件怎么路由定死，后面填性格、情感这些逻辑就不需要改接口，避免返工。

## 第 8 页 风险与待办（重点页，约 45 秒，诚实讲）

**屏幕上有**：4 行风险表 + 底部结论（风险可控，唯一硬依赖是 Ubuntu 环境）。

**主讲话术**：
> "风险页我列了 4 项。第一项是 Ubuntu 编译和实机验证还没做——这是唯一硬性依赖，我在 Windows 上验证了逻辑，但真实 ROS 环境的编译、16 项接口、全流程 demo 需要在 Ubuntu 上跑一遍。第二项是背包语音（TTS）节点还没实现，这周决策语音是降级处理，计划 W4 接入，不影响主线。第三、四项是并行协作和双机联调，接口我都备好并登记了，等设备就绪。"

**追问应答**：
- *为什么 Ubuntu 还没验证？* 逻辑验证在 Windows 就能做，但 ROS2 需要 Ubuntu 环境，我这边暂时没有可用的环境/机器，所以这周只能做到纯逻辑层面。
- *会不会拖慢整体进度？* 不会。逻辑层已经验证过，Ubuntu 侧是编译和跑通的问题，不是设计问题，风险可控。
- *TTS 没做会不会影响演示？* 不影响，有降级方案（记日志），答题、动作、状态刷新这些主链路都是通的。

| 什么时候能补完 Ubuntu 验证？ | 拿到环境后 1~2 天内可完成：编译 16 接口、冒烟、一键 demo 全流程 |

| 9.18 目标能达成吗？ | 按目前节奏能：主链路已闭环，剩下 W4-W7 是按计划逐步加功能（决策、日记、火花、稳定性） |
| 需要什么资源/支持？ | ① Ubuntu + ROS2 环境（编译验证）② 与组员的联调时间 |
