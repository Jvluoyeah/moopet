## 一、演示定位与一句话思路

**定位**：不依赖真实机器狗硬件，用 ROS2 仿真和模拟数据，
把「**感知 → 加点 → 升级 → 答题 → 决策反应**」这一整条软件流程跑通，
验证软件架构和养成体系已经就绪、后续可迁移到实体机器狗。

**一句话思路**：
> 前两周把基础打好（接口、感知、成长），第三周把答题和决策接上，
> 让整条流程首尾连起来——从摸它一下到狗狗开口回应。

## 二、演示主线（三层递进，体现"基于前两周"）

| 层 | 对应周 | 演示内容 | 关键看点 |
|----|--------|----------|----------|
| 第一层 · 地基 | W1 | 工作空间三包 + 16 项自定义接口 + T/S/A 冒烟 | 先把接口协议定好 |
| 第二层 · 感知与成长 | W2 | 背包 5 节点仿真感知 + 里程遛狗 + 8 来源加点 + 升级/成就 | 能感知，能成长 |
| 第三层 · 答题与闭环 | W3 | 题库等级解锁 → 答题/连击/难度降档 → 决策引擎入口（BT 骨架）→ TTS/动作联动 → 状态卡 | 能答题，能做反应 |

> 三层是**同一套代码逐步加长**的过程：W3 的出题/判题/决策全部复用 W1 接口与 W2 结算引擎，
> 所以按顺序放一起演示最顺，也能看出是接着前两周做的。

## 四、演示环境与两种跑法

| 方案 | 命令 | 环境 | 适用 |
|------|------|------|------|
| **A · 独立演示（现场推荐）** | `python standalone_demo_w3.py` | 仅 Python 3，无 ROS | 录屏 / 彩排 / 网不好时兜底 |
| **B · 完整 ROS2 双机** | `bash scripts/start_demo.sh --machine dog / backpack` | Ubuntu + ROS2 Humble，同 ROS_DOMAIN_ID | 展示跨机 Topic 互通、真实节点 |

> 两套跑的是**同一套纯逻辑**（quiz_bank / exp_engine / decision），演示效果一致，A 稳、B 全。

## 七、容错与备选

1. **TTS 未就绪**（背包 TTS 节点 W4 接入）→ 决策引擎自动降级为日志，不影响主线；
2. **ROS/双机不可用** → 方案 A 独立演示兜底（同一套逻辑）；
3. **数据库等级不足** → quiz 自动等待重试；演示前可用预置数据直升等级；
4. **单环节故障** → 演示模块化、可跳段，保证整体完整。
