# 养成系机械狗 · 前端（羊皮纸档案册）

对应《全栈计划_社群与对战.md》第 ③④ 项：**羊皮纸设计系统 + 注册领养入社群 +
开放世界 2.5D + Three.js 锁步对战**。

技术栈刻意压到最小：**Vite + Three.js + 原生 ES 模块**，没有框架。
理由：这个前端 90% 是"渲染一张纸 + 几个交互"，引入框架反而让接手的人先学一套东西。

---

## 一、跑起来

### 方式 A：单地址演示（推荐，一个进程一个地址）

```bash
cd ../server && python run_local.py     # 若 web/dist 存在会自动一起托管
# 打开 http://127.0.0.1:8080  —— 前端 + API + 对战 WebSocket 全在这一个地址
```

要先构建前端：`cd ../web && npm run build`。

### 方式 B：开发（改代码即时生效）

```bash
cd ../server && python run_local.py     # 8080
cd ../web && npm install && npm run dev # http://localhost:5173
```

开发服务器会把 `/api` 与 `/ws` 代理到 `127.0.0.1:8080`（见 `vite.config.js`），
所以前端代码里一律用相对路径，**开发和部署走同一套路径**，不会出现"本地能跑线上 404"。

> `npm run dev` 只绑 IPv6，用 `http://localhost:5173` 访问（不要用 `127.0.0.1`）。

后端不在本机时：`MOOPET_BACKEND=http://1.2.3.4:8080 npm run dev`，
或在地址后加 `?api=http://1.2.3.4:8080`。

## 三、羊皮纸设计系统

### 三层质感（"羊皮纸"的关键）

1. **网格底纹** —— 40px 淡蓝细格（`rgba(36,71,216,.035)`），像稿纸
2. **纸张噪点** —— SVG `feTurbulence` 分形噪声叠加（`opacity .045`），去掉纯色的塑料感
3. **纤维与做旧** —— 极淡斜向条纹 + 四角渐暗

### 配色

只有两类：**纸**（paper / paper-deep / surface）与**墨**（ink / ink-soft / muted），
强调色克制地用在"可点"与"高亮"上：

| 令牌 | 值 | 用途 |
|------|-----|------|
| `--blue` | `#2447d8` | 墨水蓝：链接、当前项、可点 |
| `--signal` | `#d5ff52` | 信号柠檬：高亮、气泡 |
| `--seal` | `#a8332a` | 印章红：印章、主行动 |
| `--moss` | `#4a6b4f` | 苔绿：在线 / 健康 |

另有**夜读模式**（`data-theme="night"`）：同一套结构换纸与墨，右上角一键切换。

### 排版

衬线大标题（Noto Serif SC / Songti SC）+ 紧字距（`-.055em`）是骨架；
正文无衬线保证可读；数字等宽对齐。

### 版式隐喻：**狗狗档案册**

左栏册页目录 · 中栏纸页 · 右栏便签。所有页面共用 `pageShell()`，
中栏本身就是一张纸（`.sheet`，带装订线）。

> 设计语言参考 [adnovel.xin 开源版](https://adnovel.xin/open-source/)（MIT）后**内化重写**：
> 借鉴其"纸+墨+一点信号色"的配色思路与排版节奏，版式是我们自己的档案册隐喻，未照搬其布局。

## 四、对战：确定性锁步

### 唯一的规则实现：`src/game/sim.js`

同一份代码服务四种场景：**AI 对战 / 好友影子 / 实时联机 / 录像回放**。
为此它满足三个硬条件：

1. **纯整数**（定点数，1 格 = 256）—— 规则里不用任何 `Math.sin/cos/tan/pow`，
   因为这些函数**不保证跨 JS 引擎结果一致**；
2. **无外部状态** —— 不读 `Date`、不读 `Math.random`、不读 DOM；
   随机只在开局由 seed 派生一次；
3. **同输入同输出** —— 由 `hashState()` + `tests/sim_test.mjs` 16 项用例守着。

### 网络模型：锁步中转站

服务端**不跑模拟**，只做：撮合 → 转发输入帧 → 记录回放 → 掉线通知。

```
玩家A ──输入帧──▶ 服务端 ──转发──▶ 玩家B
                     │
                     └── 记录 [{frame, side, keys}] → 回放/对账
```

客户端这边由 `src/game/net.js` 的 **`LockstepSession`** 负责，三种模式共用它：

| 模式 | 远端输入从哪来 |
|------|----------------|
| `ai` | 本地 `ai.js` 产生 |
| `shadow` | 同上（对手的品种/等级取自社群里的另一只狗） |
| `pvp` | 从 WebSocket 来 |

所以"掉线接管"只是把远端输入源换成 AI，**不需要另写一套战斗循环**。

**锁步的规则只有一句：拿到双方对第 N 帧的输入，才推进第 N 帧。**
拿不到就停在那里等（界面显示"等待对手…"），绝不自己猜——猜了就会两端分叉。

两个实现上必须注意的点（都踩过）：

1. **会话建好之前到达的输入帧必须缓冲**。锁步永远在等第 0 帧的对手输入，
   丢了早期帧就永久卡死。
2. **座位号以服务端的 `welcome` 消息为准**。加入方是 side 1；
   如果本地会话硬编码成 side 0，服务端转发来的对手输入（side 0）会被当成
   "自己的回声"丢掉，表现为加入方永远不动。

* **掉线**：一方断开 → 另一方收到 `{"type":"peer_left","takeover":"ai"}` → 切 AI 接管，对局不卡死
* **回放**：`GET /api/match/{code}/replay` 返回 `seed + inputs`，
  交给同一份 `sim.js` 即可复现整局
* **对账**：`hashState()` 可以逐 tick 比对两端轨迹，发现分歧立刻能定位

### 渲染：Three.js 正交相机（2.5D）

品种形象是**分层 SVG 平面资源**，用"立牌"（billboard sprite）贴进 3D 场景，
形象不必重做一遍模型；正交相机 + 斜俯视正好是 2.5D 的观感。

开放世界同理，但用 Canvas 2D 等距投影（`src/lib/world2d.js`）：
那里只需要"一群狗在广场走动"，2D 更轻、点击拾取更简单。**两种投影保持一致的坐标口径。**

### 操作

`WASD` / 方向键 移动，`空格` 出刀。一局限时 60 秒。

## 五、测试

```bash
npm test                       # 模拟一致性 16 项 + 锁步联机逻辑 31 项（都不需要浏览器）
npm run build                  # 构建（语法/导入检查）

# 下面两个需要 服务端 + 前端 都起着
npm run test:e2e               # 浏览器端到端 32 项（注册→领养→世界→竞技场打一局）
npm run test:pvp               # 实时联机 17 项（两个浏览器互打 + 掉线接管）
```

**`sim_test.mjs`** 守的是锁步地基：同 seed 同轨迹、分批推进 == 连续推进、
无浮点渗入、AI 可复现、边界钳制、伤害常数、时间到按血量比例判胜负。

**`net_test.mjs`** 把两个会话用一根"虚拟网线"接起来，在 Node 里就验证了联机逻辑：
两端逐帧哈希一致、加延迟/抖动/乱序仍不分叉、缺输入时停在原地等、掉线后 AI 接管、
输入日志能完整回放。

**`e2e_pvp.py`** 是**决定性验证**：两个独立浏览器上下文（各自 WebSocket）真的对打一局，
最后比对两端算出的状态哈希——

```
OK    两端状态哈希一致（证明跑的是同一局）  — A=0x3563feae B=0x3563feae
OK    两端结算帧号一致  — A=1800 B=1800
```

再加一个场景：中途关掉 B，A 必须收到掉线通知、切 AI 接管、并继续推进（不卡死）。

**`e2e_smoke.py`** 走真实浏览器：注册 → 领养 → 总览 → 开放世界（读画布像素确认真的画了东西）
→ 档案卡 → 排行榜 → 设计系统 → 夜读主题 → 竞技场真打一局并上报领奖。
全程收集 console 报错与失败请求，顺带把截图存到 `tests/shots/`。
