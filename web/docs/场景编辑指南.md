# 怎么自己改开放世界的场景模型

> 这份是给"想动手改地图"的人写的。里面的每一条都是这个项目里实际踩出来的，
> 不是通用教程。改之前请把第 1 节读完 —— 那里有一个坑，几乎每个新上手的人都会掉进去。

---

## 0. 两种改法，先选一种

### 改法 A（推荐）：在浏览器里直接摆 —— 场景编辑器

```powershell
npm run dev          # Vite，存盘热更新（不用再 npm run build）
# 打开 http://localhost:5173/#/world
```

1. 按 **F2** 打开编辑器面板（右上角）
2. 在列表里点一个模型选中它 —— 地上会出现**黄色圆环 + 一根竖直光柱**
   （穿透楼体画在最上层，所以选一栋楼也看得见它在哪）
3. **推着走**：
   - 面板上的按钮：`x` 和 `z` 各有 `−100 / −25 / +25 / +100`
   - 或键盘方向键：`←` `→` 是世界 x，`↑` `↓` 是世界 z
     （`Shift` = 100 格，`Alt` = 1 格；不按修饰键 = 25 格）
4. **抬升 / 下沉**：`PageUp` / `PageDown`，或面板上 `y` 那一排按钮
   - 数据里会写成 `y: 210`；不写就是贴地
   - **抬到 180 以上就不再挡路**：碰撞盒是二维的（只有 x/z），表达不了
     "从底下走过去"，所以悬空物的碰撞体会被丢掉（180 的来历：狗显示高 135）
5. 面板会**实时显示这个模型有没有穿模**（和检查器用同一把尺子）
6. 每次挪动，面板顶部会写出 **`x/z (1300,760) → (1325,760)`** ——
   25 格在画面上可能只有十几像素，光看容易以为没动，所以文字反馈也给你
7. 底部那行代码**直接复制、粘回场景文件**就行 —— 坐标已经按该场景的坐标系
   算好了（广场是世界坐标，其余三个是相机的 F/R），不用你手算

适合：调位置、试摆法、对不对称。**这是以后摆模型的主要方式。**

### 改法 B：直接改数据文件

```powershell
# 1) 改数据（只改这两个文件）
#    src/world/scenes/plaza.js    广场
#    src/world/scenes/others.js   公园 / 狗窝 / 竞技场
npm run dev      # 存盘即生效

# 2) 语法自检 + 量排布（穿模 + 取景）
node --check src/world/scenes/plaza.js
node tools/layout_check.mjs            # 不带参数 = 四个场景全查

# 3) 出图确认（10 个机位 + 每张一份纯画布裁切图）
python tests/world_shots.py http://127.0.0.1:8080 after plaza

# 4) 回归
python tests/e2e_world.py      http://127.0.0.1:8080   # 39/39
python tests/e2e_world_pvp.py  http://127.0.0.1:8080   # 27/27
```

适合：加新楼/新道具、改尺寸配色、批量挪一片。

> ⚠️ 不用 `npm run dev` 的话，改完必须 `npm run build` ——
> 后端服务的是 `w6/web/dist`，不重建你看到的是旧的。

## 0.1 高度（y）是怎么工作的

**这个场景格式原本没有 y 轴。** 所有 maker 都硬写 `grp.position.set(p.x, 0, p.z)`，
物件贴地生成、靠内部偏移往上叠（长椅坐面 `seat.position.y = B.seat`、
路灯灯杆 `pole.position.y = 560/2`…），想抬一个东西只能去改它 maker 里的几何。

现在能写了：数据里加一个 `y` 字段（单位：格），`buildScene` 会整体抬起来。
不写就是 0，**所以对已有场景完全没有影响**（改完之后 `layout_check` 的输出
逐字未变，我核对过）。

```js
prop(1678, 1020, { kind: 'fountain', r: 55, y: 210 }),   // 整体抬高 210 格
```

两条要知道的规则：

1. **碰撞盒是二维的**（只有 x/z）。所以物体抬到 **180 格以上**（狗显示高 135）
   就把碰撞体丢掉了 —— 否则会在半空留一堵看不见的墙。
   180 以下仍然照常挡路。
2. **影子会跟着物体走**：抬起来的东西，影子落在地面上，看起来就是"浮空"。
   如果那正是你要的效果就没事，否则别抬。

**"某个模型看起来浮空/陷进地里"通常不是 y 的问题**，而是它的 maker 里几何没接上
地面。这种情况正确的改法是去 `build.js` 里那个 `makeXxx()` 改内部 y，
或者调它的尺寸参数 —— 不是加一个 y 偏移把它盖住。

## 0.2 编辑器里那两个按钮

- **复制这行**：把当前选中模型的完整代码行复制到剪贴板。它是**完整**的
  （招牌、配色、屋顶、卷帘门都在），可以直接替换掉场景文件里的那一行。
- **改动清单**：列出这次会话里改过的所有模型，格式是
  `// 名字 (旧坐标) -> (新坐标)`，用来回顾刚才都动了什么。

编辑器只改**内存里的场景数据**，不会写回文件 —— 所以刷新页面就恢复原样，
放心试。定稿了再复制代码粘回文件。

## 0.3 和外部软件（Blender 等）互通

### A. 导入你自己做的模型 —— **项目本来就支持，不需要编辑器**

外部模型走的是 glTF：`public/models/` 下的 `.glb`，由 `GLTFLoader` 加载
（`src/world/models.js`）。Blender 原生导出 `.glb`，流程是：

1. **Blender 里建好模型** → `File > Export > glTF 2.0 (.glb)`
   - **尺寸随便**，不用管绝对大小（见下面第 1 条）
   - **脚底/原点随便**，会被自动对齐到地面
   - Y-up 用 Blender 的默认导出设置即可（它自己转）
2. 文件丢进 `w6/web/public/models/<你的目录>/`
3. 在 `src/world/models.js` 里登记：
   ```js
   export const MODELS_BY_KIND = {
     tree: ['tree_default.glb', '你这棵树.glb'],  // 加进已有 kind = 变成变体之一
     石头灯: ['stone_lamp.glb'],                 // 新 kind，场景里就能 kind: '石头灯'
   };
   export const TARGET_HEIGHT = { 石头灯: 300 };  // 世界单位下的目标高度
   ```
4. 场景数据里用起来（或用 §0 的编辑器摆）：
   ```js
   prop(1250, 1300, { kind: '石头灯' }),
   prop(1400, 1300, { kind: '石头灯', h: 420 }),   // 单独指定高度
   ```

**四条要知道的**：

- **高度是按包围盒归一化的**：`instanceModel` 里 `scale = targetHeight / 包围盒高`，
  再把 `-box.min.y` 挪到 0。所以你只管**比例**，不管绝对尺寸 —— 这是这套管线最省事的地方。
- **模型朝向**：`rotY` 默认按场景序号轮换（`index * 1.7`，避免一整排树长得一样），
  要固定朝向就在数据里写 `rotY`。
- **材质默认保留模型自己的颜色**。要跟这游戏的"纸盒"配色统一，得在
  `MATERIAL_PALETTE` 里**按材质名**登记替换色。注意 Kenney 那套的
  `baseColorFactor` 是**线性空间**的，直接显示会偏淡 —— 所以原作者才做了换色表。
- **要低模**。这游戏在软件光栅下跑（实测 `dpr 0.6 / 27fps / 346 draw calls`），
  而且模型是**进场时一次性预载**的（`preloadModels`，好让 `buildScene` 保持同步）。
  塞几个高模进去，进场会变慢、帧率会掉。
- 新 kind **默认不挡路**：碰撞盒由 `build.js` 的 `SOLID_PROPS` / `SOLID_DEFAULT`
  决定，要让它挡路得去那里登记。

### B. 把整个场景导出去看/量/改外表 —— 「导出 GLB」

编辑器面板上的 **导出 GLB** 把当前建好的场景（楼、道具、地面全都在）序列化成一个
`.glb`，**Blender 直接打开**。用来：核真实比例、量尺寸、改配色出效果图、渲染。

⚠️ **这是单向快照。** 在 Blender 里挪了东西再导回来**接不上** —— 场景是按数据
程序化生成的（楼是 `box()` 参数、道具是 kind + 坐标），没有"用外部网格替换场景"
这条路。要改布局用下面的 C。

### C. 在外部改坐标再导回来 —— 「导出 JSON / 导入 JSON」

这是真正能**闭环**的那条。导出的 JSON：

```json
{ "scene": "plaza",
  "items": [ { "id": "block#0", "kind": "狗粮铺", "x": 220, "z": 760, "y": 0 },
             { "id": "prop#3",  "kind": "bench",  "x": 690, "z": 1030, "y": 0 } ] }
```

用任何工具改（Excel、Python 脚本、Blender 里当空物体摆完读坐标都行），再用面板上的
**导入 JSON** 读回来 —— **立刻生效**，不用重建、不用刷新。

实测：导出 29 个 / 导入 29 个，外部改的 x/z/y 全部生效。

`id` 是 `类型#下标`（`block#0` / `prop#3` / `local#1` / `portal#0`），对应场景文件里
数组的顺序 —— **别在外部增删条目**，只改坐标；增删模型还是在文件里做。

### D. 在 Blender 里搭好整个场景，导进来当场景 —— **已支持**

场景数据里声明 `imported` 就行：

```js
PLAZA.imported = {
  url: 'models/scenes/plaza.glb',          // 相对 public/，Blender 导出的 .glb
  scale: 1,                                 // 可选，整体缩放
  y: 0,                                     // 可选，整体抬升
  colliders: [                              // 挡路的地方，**必须自己声明**
    { x: 220, z: 760, w: 400, d: 380 },     // 世界坐标中心 + 宽深
  ],
};
```

**工作流**：

1. 编辑器面板按 **导出 GLB** → 拿到当前场景（楼、道具、地面全在）→
   **Blender 打开它**当作参考底图（比例、坐标都能对着量）
2. 在 Blender 里搭你的场景 —— **用世界坐标**，glTF 是 Y-up，
   原点对齐世界的 (0,0)
3. 导出 `.glb` 丢进 `w6/web/public/models/scenes/`
4. 按上面的格式声明 `imported`；`colliders` 用 Blender 里量到的包围盒填
5. 页面**自动预载**（`pages/world.js` 会遍历 `SCENE_LIST` 收集所有
   `imported.url` 一起预载），不用你手动登记

**四条要先知道的**：

- **外部网格是静态装饰**：进不了编辑器、也不吃参数化那一套。
  改一个招牌要回 Blender 重导。
- **碰撞不会自动算**。外部几何是任意网格，推不出轴对齐盒子 ——
  `colliders` 不写就是**可以穿过去**。
- **可以和 blocks/props 共存**。推荐用法：外部场景铺**大体**
  （地形、道路、大件建筑），需要参与玩法的东西（传送门、交互物、NPC、
  要参与穿模检查的道具）继续用 `blocks` / `props` 放。
- **别放高模**。外部场景和模型一样是进场时一次性预载的，
  而且这游戏在软件光栅下跑。

**实测过**（用一个现有模型当外部场景跑完整链路）：
带 `imported` 时场景根节点 15 个、摘掉后 14 个（**导入贡献 1 个节点 ✓**）；
碰撞体 7 / 6（**声明的盒子生效 ✓**）；无报错。

## 1. ⚠️ 两个坐标系（最容易搞错的地方，没有之一）

**两个文件用的坐标系不一样：**

| 文件 | 写法 | 坐标含义 |
|---|---|---|
| `plaza.js` | `prop(x, z, {...})`、`box(x, z, w, d, h, {...})` | **世界坐标** |
| `others.js` | `prop(F, R, {...})`、`bld(F, R, w, d, h, {...})` | **相机坐标**，由 `at()` 自动转成世界坐标 |

`others.js` 顶部有：
```js
const prop = (F, R, o) => ({ ...o, ...at(F, R) });
const bld  = (F, R, w, d, h, o) => ({ ...building(w, d, h, o), ...at(F, R) });
```

`at()` 的换算（`place.js`）：
```
yaw = scene.camera.yaw
fx = -sin(yaw)   fz = -cos(yaw)      // 前方
rx =  cos(yaw)   rz = -sin(yaw)      // 右方
x = spawn.x + F*fx + R*rx
z = spawn.z + F*fz + R*rz
```

**踩错会怎样**：把世界坐标写进 `others.js`，`at()` 会再转一次，道具直接飞到
房间外面（我干过：地毯落到 x=1594，而右墙在 x=1415）。

**怎么避免**：改 `others.js` 时用工具定位，不要手算 F/R ——
```powershell
python _refs/_nudge.py <场景> <当前世界x> <当前世界z> <目标世界x> <目标世界z>
# 它把每行 F/R 正算成世界坐标、找最近的一行、再写入新 F/R
# 最近匹配超过 80 格会拒绝写入（防止"挪错了旁边的东西"）
```
反过来想知道某行 F/R 对应世界哪里：`node tools/fr2world.mjs`（只对 plaza 有意义，慎用）。

## 2. 场景对象长什么样

```js
export const PLAZA = {
  code: 'plaza',                 // 路由 / 存档用的 id
  name: '长夜月广场',             // 界面上的名字
  desc: '……',
  sky: '#f2ede1',                // 天空/背景色

  size: { w: 2200, d: 1700 },    // 地面板块尺寸，**从 (0,0) 起算**
  spawn: { x: 1100, z: 1200 },   // 狗出生点；相机绕它转、F/R 也以它为原点
  camera: { dist: 2500, yaw: -0.18, pitch: 0.95 },

  ground: { kind: 'checker', colors: ['#f8f3e7', '#e5dac1'], tile: 220, border: '#c9bb9c' },
};

PLAZA.blocks  = [ /* 楼 */ ];
PLAZA.props   = [ /* 纯装饰道具 */ ];
PLAZA.locals  = [ /* NPC / 可交互物，必须带 id 和 label */ ];
PLAZA.portals = [ /* 传送点 */ ];
```

- `size` 决定地面板块和**裙边**的位置，也决定狗的移动边界（会被 clamp）。
- `spawn` 同时是取景原点和 `at()` 的原点，**动它等于动整个场景**。

## 3. 加一栋楼

```js
// plaza.js：世界坐标
box(760, 760, 400, 380, 460, {
  color: '#f3ead9', roof: '#8c3b2e', roofH: 150,
  awning: '#a8332a', shutter: 0x8c3b2e,
  sign: { text: '汪记小馆', color: '#a8332a' },
});

// others.js：相机坐标
bld(430, -640, 520, 300, 170, { color: '#f4eedd', roof: false, sign: {...} });
```

参数：`(x, z, 宽, 进深, 墙高, opts)` / `(F, R, 宽, 进深, 墙高, opts)`

`opts` 常用项：`color` 墙色、`roof` 屋顶色（`false` = 不盖顶）、`roofH` 屋顶高、
`eave` 挑檐、`awning` 雨棚、`shutter` 卷帘门色、`sign: {text, color, vertical}` 招牌。

**硬约束**（都撞过）：
- 屋檐各向外伸 **35**，所以两栋楼的**净间距要 > 70**，否则屋顶互插。
  广场主街的间距是 **140**，是这么来的。
- `DOOR = 210`。**楼高必须明显大于 210**，否则"门比墙还高"。
  景点类的低矮棚子如果不画门（不写 `shutter`），压到 170 也没事。
- 楼是**轴对齐盒子**，所以 `w` 是 x 方向、`d` 是 z 方向，不跟着相机转。

## 4. 加一个道具

```js
prop(690, 1030, { kind: 'bench', rot: Math.PI * 0.5 });        // plaza（世界坐标）
prop(556, -81,  { kind: 'pond', w: 380, d: 260 });             // others（相机坐标）
```

可用 `kind`（`build.js` 的注册表 + 模型类）：
`tree` `bush` `grass` `flower` `mushroom` `rock` `stone` `stump`
`lamp` `pond` `bed` `bowl` `shelf` `rug` `hedge` `fountain` `stall` `stage`
`bench` `umbrella` `planter` `board`（`board` 只能放在 `locals` 里，见下）
`portalsign`（传送路牌，见 §5）

**尺寸**：多数道具的尺寸写在 `src/world/scale.js` 的 `PROP` 里，不看场景数据。
`scale.js` 顶部有一句很重要的注释：**道具尺寸都是对着狗定的**——狗显示高 135。
第一版长椅靠背 215 比狗还高，截图里像一堵木栅栏而不是"狗能坐上去的长椅"。

**摆放判据**（`layout_check.mjs` 用的真实占地）：
| 东西 | 占地 |
|---|---|
| 楼 block | `w×d` 各 +20（台基/墙厚） |
| 路灯 lamp | 26×26 |
| 长椅 bench | `w`(默认200) × 90 |
| 花坛 planter | `w`(默认140) × `d` |
| 喷泉 fountain | 半径 `r` |
| 传送圈 portal | 130×130 |
| NPC / 可交互 local | 90×90 |
| 挂墙板 board | 180×宽 × 44 深 |
| 蘑菇/花/石头/灌木/树桩 | 40 / 50 / 80 / 90 / 70 |
| `stage` | **不参与穿模判定**（`build.js` 注明它是"只在地上画圈"的地面贴花） |

## 5. NPC / 可交互物 / 传送点

### 传送点和路牌是**两件事**（2026-09 拆分）

以前一条 `portals` 数据同时生成了"功能触发圈"和"旁边的路牌"，牌子的位置是
`(-r × 1.05, 0)` **写死**的 —— 距离还跟着触发半径变，而且牌子是 billboard
（永远面向相机），连转向都做不到。现在拆开了：

```js
// 1) 传送点：**纯功能**，不再画任何牌子
PLAZA.portals = [
  { to: 'park', x: 150, z: 1620, r: 150 },
];

// 2) 路牌：普通道具，想放哪放哪、想转就转
prop(-7, 1620, { kind: 'portalsign', label: '去公园' }),
```

`portalsign` 的参数：`label` 牌面文字 · `rot` 朝向 · `y` 抬高 ·
`post` 杆高（默认 260）· `h` 字高（默认 130）· `color` 文字色（默认蓝 `#2447d8`）·
**`billboard: false`** —— 牌子默认永远面向相机（斜俯视下不这样会歪得看不清字），
设成 `false` 之后它才跟着 `rot` 转。

迁移时已经按**原来的写死位置**给每个传送点补了一块路牌
（plaza 3 块 / park 2 / kennel 1 / arena 1，位置逐一核对过），
所以视觉和拆分前一模一样 —— 但从现在起**动传送点不会带着牌子跑**，反之亦然。

`portals` 的 `to` 必须是另一个场景的 `code`，`r` 是触发半径。

```js
PLAZA.locals = [
  { id: 'board', kind: 'board', label: '公告板', hint: '……', x: 1250, z: 1300 },
  { id: 'shop-food', kind: 'npc', label: '狗粮铺·老板娘', hint: '……', x: 940, z: 1100 },
];

PLAZA.portals = [
  { to: 'kennel', ...at(150, 250), r: 150, label: '去狗窝' },   // others.js 写法
];
```

- `locals` 必须**每个都有唯一 `id`**，`label` 是浮在头上的名字，`hint` 是靠近时的提示。
- `kind: 'board'` 会画成**告示牌**（面板 + 两条腿，见 `makeBoard`）。
- `portals` 的 `to` 必须是另一个场景的 `code`，`r` 是触发半径。
  `at()` 写法在两个文件里都可以用（传送点永远是 F/R）。

## 6. 取景的三条硬约束

1. **`pitch` 锁在 45°~60°**。`tests/e2e_world.py` 有一条断言
   「相机有斜俯角（45~60°，看不到地平线）」，改成 36° 会直接挂（我试过，38/39）。
   注意 `scale.js` 的 `VIEW.pitch` 默认是 50°（0.87 rad），四个场景各自覆盖成 0.95（54°）。

2. **`pitch > 17.5°`（半视场角）意味着地平线永远在画面之上**，
   所以"越远越高的东西"会一直往画面的上边缘爬。
   楼会不会被锯掉，判据是 `顶% ≥ 0`（等价于 `占高% ≤ 楼脚%`）。

3. **调 `dist` 前先算裙边**。地面板块是有限的，顶边视线 = `pitch − 17.5°`，
   对应地面距离约 `dist·cos(pitch)/tan(pitch−17.5°)`；
   这个值一旦超过"出生点到板块远端的距离"，**地面的远端裙边就会进画面**
   （公园地面只 1900 深、出生点离远端 1350，所以 park 的 dist 卡在 1700 不能放大）。
   `dist` 的范围是 `[900, 3000]`（`camera.js` 的 `minDist`/`maxDist`）。

**结论**：楼太高顶出上缘时，**优先压矮楼**或**把楼挪近**；
`dist` 是最后手段，而且要先算裙边。

## 8. 已知的坑（照着躲）

1. **量尺曾经是错的**。`layout_check` 的尺寸表里，不写 `w/d` 的小道具
   全落到 `default: 200×200`，于是蘑菇被当成两米见方的东西 —— 报出来的
   "穿模"一半是假的。如果你看到离谱的重叠数，**先去核对尺寸表**。
2. **取景公式曾经和渲染器不一致**（表算 顶+11，实际 −6），
   所以"顶% 转正了"可能是假结论。现在表里用的是照 `camera.js` 复刻的真投影，
   自检办法：**表里"狗 玩家"那一行必须和 `_proj.py` 对得上**（现在都是 76/71）。
3. **`others.js` 的注释里有不配对的括号**，用"括号配对"找场景区块会在 284 字符处
   提前归零。要按 `export const` 划块。
4. **切场景不能用 URL**：`#/world?scene=park` 是**静默无效**的。
   场景是应用状态，得点顶部标签页，而且**点之前要等标签页渲染出来**。
5. **直接改 `world.player.x/z` 传送会被拒**（提示"位置同步异常，已忽略这一步"）。
   要移动就用 WASD，或者改 `camera.yaw`（相机绕狗转）。
6. **改 `camera.yaw/pitch` 要用鼠标拖拽**，直接赋值不生效。
   系数：`yaw -= dx*0.006`、`pitch += dy*0.004`。
7. **滚轮缩放方向**：`zoom(delta)` 是 `factor = exp(delta*0.0012)`，
   要拉近得给**负** delta。
8. **改完 `npm run build`**。后端服务的是 `w6/web/dist`，不重建你看到的是旧的。
9. **这个仓库没有 git**，改坏了没法从历史恢复 —— 动大件之前先复制一份文件。

## 9. 一次完整的改动流程（示例：把某栋楼挪远 100 格）

```powershell
# 0. 备份（没有 git！）
Copy-Item src\world\scenes\plaza.js src\world\scenes\plaza.js.bak

# 1. 看一眼现在是什么样

node tools/layout_check.mjs plaza        # 要求：0 条穿模、顶% ≥ 0

# 4. 重建 + 出图
npm run build
python tests/world_shots.py http://127.0.0.1:8080 after plaza
# 打开 tests/shots/after-01-default-canvas.png 对比 before-01-default-canvas.png

# 5. 回归
python tests/e2e_world.py http://127.0.0.1:8080
python tests/e2e_world_pvp.py http://127.0.0.1:8080
```
