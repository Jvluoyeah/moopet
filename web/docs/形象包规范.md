## 零、真实形象（当前主用）

```
web/public/breeds/<code>/
  forms/sit.png    坐    待机 / 图鉴 / 档案卡 / 大世界立牌
  forms/face.png   正面  面向镜头（对话、结算）
  forms/paw.png    挥手  打招呼 / 撒娇 / 放技能 / 冲刺 / 受击
  forms/lie.png    趴下  休息 / 倒地（KO）
  art.json         画布 512×512、脚底基线 470、每张的实际高度
```

原图放在 `pic/<中文名>/`（`主图.png` + `四种形态.jpg` 2×2 四格），
由 `python tools/slice_breeds.py` 一次切好；
质检图 `python tools/breed_forms_sheet.py` → `tests/shots/90-breed-forms.png`。

三条处理规则（改切图脚本前先读，都是踩过的坑）：

1. **抠背景用洪水填充，不用"删掉所有浅色"**。萨摩耶/比熊/哈士奇的肚子接近白，
   全局阈值会把狗掏成镂空。从四边往里灌，只吃掉真正连到边界的背景。
2. **同一张四格图里的四只按同一个缩放系数缩**。各缩各的会让"趴下"被放大成巨狗。
3. **分图靠连通域 + 重心归格，不是"每格只留最大的那一坨"**。
   后者在描边被 JPEG 压出断口时，会把断开的腿当成"隔壁的碎片"删掉——那就是截断。
   现在只在"重心落在别格、且面积小到是碎屑"时才丢。

前端取图统一走 `src/lib/breedAssets.js`：
`preloadBreedArt()` 在应用启动时预载（`main.js` 的 `boot()`），
`breedImage(code, form)` 同步取图，**取不到就返回 null**，
调用方（`ui.js` 的 `dogPortrait`、`world/actors.js` 的 `dogTexture`）据此退回 SVG。

尺寸口径：真实图是 **512×512 方形画布**，狗占中间约 78%、脚底在 y=470。
所以任何容器都必须按**正方形**等比缩放（CSS 里那条 `img.dog-portrait`），
3D 立牌也必须挂在**正方形**面上——贴到 0.78:1 的窄面上会把狗横向压扁 22%，
看着就像"被裁窄了"（战斗立牌上出现过这个）。

## 一、为什么要一套资源

一只狗的形象要在**四个地方**出现，而且要长得一样：

| 出现位置 | 用途 |
|----------|------|
| 图鉴卡（领养页） | 选品种 |
| 档案卡（dossier） | 个人档案 |
| 开放世界画布 | 2.5D 广场上的立牌 |
| 对战 / 剧情关卡 | 双方单位、Boss 与杂兵 |

如果每个位置各画一份，美术要做四遍，而且一定会不一致。
所以定成**一套资源**，四处复用。战斗里还会按状态换形态：
倒地 → `lie`，出招/冲刺/受击 → `paw`，其余 → `sit`。

## 二、兜底资源：分层 SVG（`src/lib/breedArt.js`）

真实图缺失时用它。规范如下：

```
web/public/breeds/<code>/
  breed.json          # 元信息：锚点、体型、部件偏移、毛色槽位（可选）
  layers/             # 分层 SVG（可选）
    shadow.svg        # 落地投影
    tail.svg          # 尾巴（在身体之后）
    legs.svg          # 四肢
    body.svg          # 躯干
    marking.svg       # 斑纹（面罩/马鞍/胸口白斑）
    head.svg          # 头 + 口鼻 + 眼鼻
    ears.svg          # 耳朵（在头之后，因为要盖住头顶）
    collar.svg        # 项圈（颜色随等级档位）
  preview.png         # 图鉴用预览图（可选，没有就用 SVG）
```

`code` 与 `moopet_server` 的 `breed.code` 一致：
`samoyed` / `border_collie` / `golden` / `corgi` / `shiba` /
`german_shepherd` / `husky` / `bichon`。

## 三、breed.json 字段

```json
{
  "code": "samoyed",
  "name": "萨摩耶",
  "viewBox": "0 0 200 200",
  "anchor": { "ground": [100, 182], "head": [140, 76] },
  "traits": { "ears": "erect", "tail": "curl", "build": "plush", "muzzle": "short" },
  "palette": { "fur": "#F7F4EC", "accent": "#D8D2C4", "nose": "#2B2A28" },
  "slots": {
    "fur":    { "label": "毛色",   "layers": ["body", "head", "ears", "tail", "legs"] },
    "accent": { "label": "浅色区", "layers": ["marking"] },
    "collar": { "label": "项圈",   "layers": ["collar"], "by": "level_tier" }
  }
}
```

* `anchor.ground` —— 站立点。2.5D 画布与对战立牌都以它为"脚底"，保证不同体型的狗站在同一地面上。
* `anchor.head` —— 气泡与名字牌的挂点。
* `slots` —— 换色/换皮肤的作用范围；`by: level_tier` 表示这个槽位由等级档位决定
  （普通/稀有/史诗/传说 → 灰/蓝/紫/金）。
* `traits` —— 形状骨架。当前占位实现按它选耳朵/尾巴/体型；真实插画可以直接忽略它。

## 四、技术约束

1. **必须能被当作独立 SVG 文档渲染。**
   画布（Canvas/WebGL）里的 SVG 没有 CSS 变量上下文，
   所以资源里**不能依赖 `var(--ink)` 之类的变量**，颜色一律写实色值。
   （当前占位实现在 `breedArt.js` 里通过 `theme` 参数传入具体色值来解决。）

2. **viewBox 统一 200×200**，脚底对齐 `y=182`。
   这样不同体型的狗摆在一起时不会有的悬空、有的陷进地里。

3. **图层顺序固定**（从下到上）：
   `shadow → tail → legs → body → marking → head → ears → collar → eyes`
   顺序错了会出现"耳朵长在头下面"这类问题。

4. **单文件尽量小**：每层建议 < 6 KB（广场上可能同时渲染 40 只狗）。

5. **不出现 emoji**：需求明确要求以品种形象呈现，资源里不得使用 emoji 字符。

## 五、替换步骤

1. 按上面目录放好 `breed.json` 与 `layers/*.svg`
2. 在 `src/lib/breedArt.js` 里把 `portraitSVG()` 改成：
   * 若 `public/breeds/<code>/breed.json` 存在 → 读取并拼装图层
   * 否则 → 回退到当前的程序生成占位
3. 运行 `node tests/sim_test.mjs` 与浏览器冒烟，
   确认四个出现位置都换成了新形象

> 替换是**纯资源操作**：不需要改页面、画布或对战渲染代码。
> 这也是当初选择"分层 SVG + 占位生成器"而不是直接上 3D 模型的原因。

## 六、等级档位配色（项圈）

| 档位 | 等级 | 颜色 |
|------|------|------|
| 普通 | 1–9 | `#6b6560` |
| 稀有 | 10–19 | `#2447d8` |
| 史诗 | 20–29 | `#7a3fa8` |
| 传说 | 30+ | `#b8892f` |

档位**只影响外观**，不影响数值 —— 数值来自品种四维与养成系统。
